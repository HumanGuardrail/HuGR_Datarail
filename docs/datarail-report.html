⚡ The warp number — measured on real hardware

The headline claim was "warp speed." We didn't assert it — we measured the real binary on a representative VAES server core (a cloud box with the modern AES vector instructions), because the dev laptop is a pre-VAES 2019 chip and its numbers are noise.

The two backends are wire-compatible — a known-answer test pins AES-256-GCM to one exact ciphertext that both produce byte-for-byte, so a cofre sealed by one opens on the other. Default stays pure-Rust (lightweight); the VAES backend is opt-in for throughput-critical routes. ring was already in the tree, so it added zero new dependency weight.

🔒 What the rail provably does

  • PROVEN
    The pipe can't read your data. Every payload is sealed end-to-end (AEAD + Ed25519 signature + per-cofre X25519 key-wrap). A metamorphic test swaps the plaintext under a fixed header and the substrate's byte-trace is identical — the rail provably never sees content. (AC-1 opaque-cargo.)
  • PROVEN
    Tamper is impossible to sneak through. Every single byte of a sealed cofre is flipped in a test and every flip is rejected — exhaustive, not sampled. Forged or wrong-key seals are rejected against the route-pinned key. (AC-2 / AC-3.)
  • PROVEN
    Exactly-once, even through chaos. 1000 randomized runs of drop / reorder / duplicate / kill-and-respawn → 0 loss, 0 duplicates. And over a real TCP socket partitioned mid-stream: reconnect, re-drive, dedup → still 0/0. (AC-4 / AC-8.)
  • PROVEN
    Delivery comes with a receipt. A Merkle manifest whose root an independent verifier re-derives; any tamper breaks it. (AC-5.)
  • PROVEN
    One rail, many pipes. The same conformance harness passes over all three spec-named substrates — shared-memory (µs same-host), QUIC (cross-host blind relay), object-store/S3 (cross-cloud) — plus TCP/Unix-socket. The endpoints don't know or care which pipe carries them. (AC-6, 3/3 named.)
  • PROVEN
    It runs as real, separate processes. datarail send and datarail recv move a sealed shipment between two distinct OS processes over a real socket — optionally inside a mutually-authenticated Noise_KK encrypted hop, and two hosts can bootstrap trust from a short code via SPAKE2 pairing (wrong code → burns).
  • PROVEN
    It refuses bad data at the door. Content-contract enforced on both ends; violations dead-letter with a reason, never silently corrupt. Backed by property-based testing. (AC-9.)

🏰 Why it's genuinely awesome — the moat

Three things are true at the same time, and that intersection is the moat:

  • 🛡️
    Provider-blind by construction. The infrastructure — even ours, even an S3 bucket, even a hostile peer — physically cannot open the vault. A broker like Kafka reads your messages; datarail structurally can't. That's not a setting, it's the architecture.
  • ⚡
    Sealed at near-line-rate. ~6 GB/s/core sealing means encryption isn't a tax you pay on top of the pipe — the seal is the path. A competitor that bolts encryption onto a plaintext transport pays it as pure overhead.
  • 🪶
    Featherweight & serverless. No broker, no cluster humming 24/7. The rail spawns, carries, proves delivery, and vanishes — idle cost ≈ 0 by construction.

Each piece exists somewhere (Kafka has durability; service meshes have reach; Signal has sealing). Nobody ships all of them as one rail. That synthesis — plus exactly-once and cross-substrate portability — is what doesn't exist off the shelf.

🧭 Are we trailblazing? — the frank take

Yes, on the architecture. A provider-blind, serverless, sealed-at-line-rate, exactly-once rail that runs over any dumb pipe is genuinely not a thing you can buy as one product. The synthesis is novel, and the engineering discipline behind it (spec frozen by content-hash, 6-lens adversarial audits, every gate measured not claimed) is the real edge.

No, we did not reinvent cryptography — and that's correct. We compose audited primitives (ring, dalek, SPAKE2, Noise) the right way. Inventing crypto would be a red flag, not a badge.

And here's the honest part: the warp number is real and measured, but the "obliterate Kafka" head-to-head has not been run yet. We've proven the foundation that should win on the moat dimensions — we have not yet put datarail and Kafka on the same hardware with the same workload. Until we do, "we beat Kafka" is a hypothesis with strong priors, not a result. We don't claim measured wins we haven't run.

🚧 What we have NOT proven yet

  • PENDING

  • PENDING
    The violent stress suite across the 5 flagship use cases (monstrous volumes, kill-mid-stream, duplicate/forged floods, backpressure saturation). Designed; not built yet.
  • DIRECTIONAL
    Latency & idle-footprint as formal gates. Per-cofre seal ~110–130 µs on a VAES core (amortizes per batch); idle-state ≈ 0 is architectural. Formal p50/p99 + real serverless idle-RSS still need a clean measurement rig.
  • DIRECTIONAL
    FASP-beats-lossy-TCP on a real WAN. The delay-based congestion-control algorithm is proven in unit tests; the throughput-under-loss win needs a real lossy link to measure.
  • PENDING
    Owner ratification of the trio (MF-0) — a human sign-off, not an engineering task.

🛠️ How it's built (the part that makes the above trustworthy)

  • 🦀
    Rust, #![forbid(unsafe_code)] workspace-wide — with exactly one contained, audited unsafe waiver (the lock-free shared-memory ring), reviewed line by line.
  • ✅
    clippy deny(all + pedantic), zero #[allow] — the gates are real teeth, not decoration. Green on both the default and the vaes build.
  • 🧊
    Spec frozen by content-hash before any code; the cross-crate contract re-freezes with a logged ritual whenever the sealed-envelope seam changes.
  • 🔬
    Adversarial audits + cold verification — findings are verified in the cited code before action; self-reported "greens" are never trusted (a sub-agent's wrong test count and a hardware mislabel were both caught this way).

Bottom line. The rail is built, tested (141 green), audited, and — on representative VAES hardware — seals data at ~6 GB/s/core while remaining provider-blind. That combination is the moat, and it's measured, not promised. The thing left to prove (not build) is the head-to-head that turns "should win" into "did win." That's the next round.
